## 申请条件与尚待确认的资格

官方流程：vivo商业账号注册并实名认证 → 在Health Kit平台创建应用 → 申请开通服务、提交资质、选择数据权限 → 审核通过获测试权限 → 联调 → 申请发布服务。

申请说明的示例资质页包含申请材料、公开隐私政策链接、公开用户协议链接、企业/应用官网链接和邮箱；模板具体条目及现行要求仍需在登录后的入口核实。敏感数据权限须人工审核。说明页写有约7个工作日的审核周期，不保证实际完成时间或获批。

**个人开发者、学生或个人开源项目是否可申请并签约，尚未从公开材料得到明确结论。** 不将企业合作的案例推广为所有申请人必须拥有企业，也不承诺个人实名认证后必然可开通。注册账号不等于获得Health Kit数据权限。

## 云端接入的具体要求

- 取得应用App ID、App Secret。Secret保存在受控服务端，不写入skill、公开仓库或手机安装包。
- 用户经H5页面授权，通过配置的redirectUri接收一次性code；该回调地址需要联系vivo配置。
- 需要向vivo提供服务端出口IP。私有电脑运行的服务不因此自动满足公网回调和出口IP要求。
- 请求采用POST及HMAC-SHA256、URL Safe Base64签名。实现应以实际发送的请求体字节计算签名，不能混淆字段名大小写与字段值。
- code文档有效期30分钟、仅可用一次；accessToken默认30天、refreshToken默认180天，需处理刷新、取消授权与失效。
- 运动记录推送接收地址要求HTTPS，并以 `/vivo/healthKit/push/exercise` 结尾。
- 文档描述开发中状态的线上测试接口开放50天，可联系延长；正式使用需发布服务。服务有效性还与签约合同期限有关，不能把测试应用视为永久免费授权。
- FAQ明确云服务不能由客户端直接接入。这是该云路线的要求，不据此否定简介提及的独立本地API；当前本地接入路线尚未评估。

## 跑步记录的取得方式与限制

| 能力 | 官方定义 | 实测状态 |
| --- | --- | --- |
| 新运动记录 | 向第三方服务端推送；要求有效账号授权及运动记录权限 | 尚未部署接收服务、取得授权或收到推送 |
| 活动列表 | POST `/cloud/exercises`，返回运动ID列表 | 未调用 |
| 活动详情 | POST `/cloud/exercise`，返回ExerciseInfo | 未调用 |
| 日常步数 | POST `/cloud/steps` | 未调用；不能扩展为睡眠、HRV覆盖 |

列表和详情章节写明仅支持最近一个月、限流且用于兜底，主要依靠推送。列表参数又写单次时间区间不超过31天、开始时间不超过当前时间1年；两处口径需要向vivo确认，**不能据后一条承诺可回溯一年**。不得用高频轮询替代推送。

记录上云及推送存在时延，手表与手机连接、手机网络和上云设置都会影响到达。FAQ提示非vivo手机暂不支持、过低Android版本也可能不支持；iQOO具体机型、系统、健康App版本及手表组合应逐一核实，不据品牌直接判定兼容。没有已核实的秒级延迟承诺，也没有据此确认跑步过程中持续传输实时指标。

## ExerciseInfo模型中与跑步有关的字段

下列为**文档定义**，不是已收到的真实数据，更不代表每台设备均返回全部指标。

| 层级 | 字段及语义 |
| --- | --- |
| 基础概要 | eid、运动类型、开始/结束毫秒时间戳、distance米、costTime毫秒、calorie千卡 |
| 平均指标 | avgHeartRate、averageSpeed公里/小时、stepRate步/分钟、pace步幅米、totalStep；pace在该模型中不是配速 |
| 运动序列 | heartChart、speedChart、cadenceChart、altSportChart中的实际采集点与时间；采样间隔不猜测，gap字段注明存在但不使用 |
| 公里段数据 | paceChart，以公里编号及秒记录；不足一公里使用特殊标记，不能当作每一段都是完整公里 |
| 轨迹 | trackInfos，经纬度、采集时间、运动/暂停/恢复/GPS异常等状态；坐标系及完整性仍需核实 |
| 可选派生值 | recoveryTime恢复时间分钟、vo2Value、有氧/无氧强度、运动强度分布等；缺失时不补造，不拼成其他品牌量表 |
| 质量与来源 | abnormalData、paused、source手机/手表等；需按实际返回值复核 |

该文档不证明已有日常睡眠、HRV、静息心率接口可供本项目读取。推送参数表与JSON示例还存在exerciseInfo外层包装表述差异，实施前需确认实际请求格式和签名规则。

## 本项目的下一步

1. 核实配对手机、系统和健康App兼容性，以及个人申请资格、所需材料、合同和费用；不先购买服务器。
2. 资格明确后，由项目所有者完成实名认证、申请及必要签约；仅申请实际需要的读取权限。
3. 获批后配置受控服务端、HTTPS回调及出口IP，完成一次本人授权和新活动推送试验。
4. 与App核对同一活动的时区、单位、计时、距离与有记录的序列，再测试重试、重复推送、撤权、补拉和同步延迟。
5. 新活动推送验证通过后，才将该连接列为可用。开源代码的许可证不会自动授予下游使用者平台调用权限；每个部署的应用凭证和签约安排需另行明确。

尚未向vivo发送邮件、提交申请、注册账户或部署公网服务。
